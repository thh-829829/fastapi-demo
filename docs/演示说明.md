# v1.0.0 面试演示说明

## 一、演示目标

面试演示控制在 5 至 8 分钟，重点展示四个能力：

1. RAG 知识库文档上传、向量入库和 SSE 流式问答。
2. Agent 目标创建、任务拆解、上下文记忆和工具调用。
3. JWT、RBAC、MySQL、ChromaDB 和 Agent 工具三层数据隔离。
4. 问答日志、异常兜底、测试覆盖和 Docker Compose 部署。

## 二、演示前准备

1. 确认四项容器正常运行：

```bash
docker compose ps
```

2. 准备一个测试账号和一个管理员账号。
3. 准备一份不含敏感信息的测试文档。
4. 浏览器打开 `http://服务器公网IP/`。

## 三、推荐演示流程

### 1. 登录与数据范围

在页面顶部粘贴普通用户 Token，确认状态显示：

```text
已登录：用户名（user）
```

说明：

- JWT 中只以当前用户身份访问数据。
- 普通用户无法访问管理员接口。
- 跨用户访问目标、任务和文档统一返回 `404`。

### 2. 文档上传与 RAG

上传测试 PDF 或 DOCX，等待页面提示“上传成功”。

提问：

```text
请用三点概括这份文档的主要内容。
```

展示：

- 回答以 SSE 流式输出，不需要等待完整结果。
- 回答来源来自当前用户私有知识库。
- 问题、回答摘要、耗时、命中和状态会写入 `qa_logs`。

### 3. 学习管家 Agent

将对话模式切换为“学习管家”，输入：

```text
创建一个学习目标“FastAPI 企业级应用”，
并创建一个关联任务“完成 RAG 与 Agent 联调”，优先级高。
```

随后询问：

```text
请列出我当前的所有目标和任务。
```

展示：

- Agent 自动选择 `create_goal`、`create_task` 和 `list_tasks` 等工具。
- 目标和任务真实写入 MySQL。
- Redis 保存多轮会话上下文。
- Agent 工具始终绑定当前 JWT 用户，不能跨用户操作。

### 4. 管理员后台

切换管理员 Token，进入“管理后台”，依次展示：

- 用户管理：邮箱脱敏，不返回密码。
- 文档管理：只返回元数据，不返回正文。
- 问答日志：问题、摘要、耗时、命中和状态。

### 5. 部署与测试

展示：

```bash
docker compose ps
.\venv\Scripts\python.exe -m pytest -o addopts='' -q
```

说明 Docker Compose 包含 FastAPI、MySQL、Redis、ChromaDB 四个服务，并通过健康检查控制启动顺序。

## 四、面试讲解重点

- 为什么使用 ChromaDB 元数据过滤实现用户级向量隔离。
- 为什么上传和检索必须使用同一个 Embedding 模型。
- 为什么日志写入失败不能阻断问答主流程。
- 为什么保留普通 RAG 和 SSE 两条问答链路。
- Agent Function Calling 与普通问答的区别。
- 数据上传失败时如何回滚 MySQL 和向量库。

## 五、当前边界

- 面试演示版本使用公网 IP 和 HTTP，不购买域名。
- 生产环境应增加域名、HTTPS、限流、审计告警和数据库备份。
- 大规模场景需要拆分向量服务、异步任务和日志检索服务。
