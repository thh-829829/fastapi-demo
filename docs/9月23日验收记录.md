## 二、本轮修复

### 1. 向量库连接改为惰性初始化

原来的 ChromaDB 全局对象在模块导入时立即连接 HTTP 服务，导致以下问题：

- 执行自动化测试时，测试尚未开始就因 ChromaDB 未启动而失败。
- 仅使用注册、登录、目标任务等非 RAG 接口时，应用也会被外部服务阻塞。

现在 `VectorStore` 只保存连接参数，第一次真正执行向量操作时才连接和创建集合。连接失败时返回明确运行时异常，由对应接口转换为友好错误。

### 2. 数据库迁移支持全新环境

原初始迁移默认 `users`、`goals`、`tasks` 和 `documents` 表已经手工存在，在全新 MySQL 上直接执行 `alembic upgrade head` 会失败。

现在初始迁移会：

- 空库场景：依次创建 `users`、`goals`、`tasks`、`documents`、`qa_logs`。
- 旧库场景：保留已有业务表，只补齐 `users.role` 和 `qa_logs`。
- 重复执行：已有表、字段和索引会跳过，不重复创建。

### 3. Alembic 接入统一配置

`alembic/env.py` 不再依赖 `alembic.ini` 中的固定数据库密码，而是从 `.env` 或环境变量读取 `database_url`。容器内可直接复用后端配置。

### 4. Compose 启动顺序和地址修复

`docker-compose.yml` 已补齐：

- FastAPI 容器内使用 `mysql`、`redis`、`chromadb` 服务名。
- MySQL 和 Redis 健康检查，健康后再启动 FastAPI。
- FastAPI 启动前自动执行 `alembic upgrade head`。
- MySQL、Redis、ChromaDB 命名数据卷。
- Compose 对后端环境变量进行显式覆盖，避免误用本机 `localhost`。

### 5. 启动流程收口

已移除应用启动事件中直接执行 `Base.metadata.create_all()` 的做法。数据库结构统一由 Alembic 管理，避免“建表成功后再执行迁移发生表冲突”。
