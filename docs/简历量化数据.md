## 二、推荐简历描述

### 版本一：强调工程完整度

基于 FastAPI、MySQL、Redis、ChromaDB 构建 AI Agent 智能学习助手，完成 22 条 API 路径、29 个 API 操作和 6 个 Agent 工具；通过 JWT + RBAC 实现双角色权限，并完成 MySQL、向量库和 Agent 三层用户数据隔离。

### 版本二：强调 RAG 与性能

实现 PDF/DOCX 解析、文本分块、BGE 中文向量化、ChromaDB 检索和 SSE 流式问答；使用 Redis 缓存重复问题，热门问答可毫秒级返回，并记录完整问答耗时、知识命中和异常日志。

### 版本三：强调质量与部署

使用 Docker Compose 编排 FastAPI、MySQL 8、Redis 7 和 ChromaDB，配置健康检查和持久化数据卷；建立 42 条自动化回归测试，覆盖权限、跨用户越权、主流程、上传回滚、日志失败和容器配置。

## 三、STAR 表述示例

### 项目背景

传统学习资料分散，用户难以基于个人文档持续问答，也无法把知识库、学习目标和任务执行统一起来。

### 任务目标

构建一个个人知识库驱动的 AI 学习助手，同时满足多用户数据隔离、流式问答、Agent 工具调用、日志审计和可部署性。

### 关键行动

- 设计 REST API、Service、ORM、工具客户端四层结构。
- 接入 DeepSeek 对话与 Function Calling。
- 使用硅基流动 BGE 完成中文 Embedding。
- 用 ChromaDB 保存用户隔离的文档分块。
- 用 Redis 保存缓存与 Agent 上下文。
- 用 Docker Compose 统一部署四项服务。
- 用 42 条测试覆盖主流程、权限和异常场景。

### 项目结果

- 22 条 API 路径和 29 个 API 操作可运行。
- 6 个 Agent 工具可完成目标、任务、进度和知识库操作。
- 16 条权限测试覆盖 `401`、`403`、`404` 和越权场景。
- 公网环境通过 Nginx + Docker Compose 提供演示入口。

## 四、面试时避免夸大

- 当前版本是个人项目，不要描述为高并发生产系统。
- HTTP + 公网 IP 只用于演示，不要声称已经满足生产安全标准。
- 当前没有大规模性能压测数据，应使用“功能回归耗时”而不是“QPS”。
- Agent 工具数量为 6 个，不把框架内置能力算作自研工具。
