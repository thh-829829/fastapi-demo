# 权限矩阵（RBAC v1）

文档基线：2026-09-20。矩阵是目标权限定义，括号中的日期表示对应能力的计划落地节点。

## 一、角色定义

| 角色 | 说明 | 典型用户 |
|------|------|----------|
| user | 普通用户，只能操作自己的数据 | 所有注册用户 |
| admin | 管理员，在 user 基础上额外拥有全局查看/管理能力 | 开发者本人、运营 |

## 二、资源 × 动作 × 数据范围

| 资源 | 动作 | user | admin | 数据范围说明 |
|------|------|:----:|:----:|--------------|
| 个人资料 GET /users/me | 查自己 | ✅ | ✅ | 仅自己 |
| 个人资料 PUT /users/me | 改自己 | ✅ | ✅ | 仅自己 |
| 目标 goals CRUD | 增删改查 | ✅ | ✅ | user：仅 user_id=自己；admin 全局管理属于后续扩展，不作为 9 月企业级 MVP 硬性项 |
| 任务 tasks CRUD | 增删改查 | ✅ | ✅ | user：仅 user_id=自己；admin 全局管理属于后续扩展 |
| 文档 documents CRUD | 增删改查 | ✅ | ✅ | user：仅 user_id=自己；9 月 18 日完成本人删除时同步清理向量分块 |
| RAG 问答 POST /ask | 提问 | ✅ | ✅ | 检索只命中 user_id=自己 的分块（9.16） |
| Agent 对话 | 对话 | ✅ | ✅ | 工具调用只能传 current_user_id（9.16） |
| 问答日志 qa_logs | 查看 | 仅自己（可选） | ✅ 全局分页 | 按 user_id / 时间 / 关键词筛选（9.17） |
| 用户列表 GET /admin/users | 查全部 | ❌ 403 | ✅ | 邮箱脱敏、不返回密码（9.18） |
| 修改用户角色 PUT /admin/users/{id}/role | 改角色 | ❌ 403 | ✅ | 仅 admin；列为后续扩展，不属于 9 月 18 日最小接口 |
| 全局文档管理 GET /admin/documents | 查全部 | ❌ 403 | ✅ | 看全局文档元数据（9.18） |

## 三、三条铁律（后续每天写代码都要遵守）

1. 所有业务查询必须带 `user_id == current_user.id` 过滤，禁止裸查全表。
2. ChromaDB 分块 metadata 必须写 `user_id`，检索时按 `user_id` 过滤。
3. Agent 工具函数必须接收 `current_user_id` 参数，禁止出现硬编码 `user_id=1`。

## 四、错误码约定

| 场景 | HTTP 状态码 | detail |
|------|:-----------:|--------|
| 未带 token / token 过期 | 401 | 无效身份凭证 |
| 已登录但角色不足 | 403 | 权限不足 |
| 资源不存在 | 404 | 资源不存在 |
